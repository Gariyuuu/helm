## What this project is

Helm is a **Personal Command Center / Life OS** — one system across school,
career, research, projects, learning, health, and personal life that ranks
what actually matters and answers "what should I be doing right now, and
why?" Every nav destination is a real page (no stubs). Repo is **public**
on GitHub (`github.com/Gariyuuu/helm`) even though it stores real personal
data — see `SECURITY_REVIEW.md` before assuming "public repo" means "no
sensitive concerns."

Live at `https://helm-lovat-theta.vercel.app` (content-verified 2026-08-17
— see `DEPLOYMENT.md`; this contradicts an older `HANDOFF.md` claim that
it wasn't deployed, corrected this pass).

## Stack

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Tailwind CSS 4
· shadcn/ui (`radix-nova`) · Clerk · Neon Postgres · Drizzle ORM · Vitest.
Exact dependency versions: `package.json`.

## Commands

```bash
pnpm dev          # http://localhost:3000
pnpm build        # production build
pnpm lint         # ESLint, includes Next 16's react-hooks/purity rule
pnpm typecheck    # tsc --noEmit
pnpm test         # vitest run — currently one suite (priority engine)
pnpm db:generate  # drizzle-kit generate
pnpm db:push      # drizzle-kit push (no migration history yet)
pnpm db:seed      # needs SEED_CLERK_ID to attach to a real account
```

`drizzle-kit` doesn't read `.env.local` on its own —
`set -a && source .env.local && set +a` first.

## Critical rules

- **This is a real, deployed personal app with real personal data** (once
  seeded/used) — school, career, health, finance. Treat it with the care
  of a production app, not a scaffold, even though its own docs said
  "not deployed" until this pass corrected that.
- **Every server action must call `requireUser()` and scope queries by
  `userId`.** `src/proxy.ts` gates routes, but per Next's own guidance
  (and this codebase's existing convention, spot-checked in
  `work-items.ts`/`settings.ts`), authorization is enforced again in every
  action — don't add an action that skips this.
- **Domain-scoped verticals (Personal/Health/Finance/Relationships) have
  no dedicated tables** — they're `work_items` filtered by
  `life_domains.slug` through `src/components/domain/domain-work-view.tsx`.
  Don't create a new table for a "life area" without first checking
  whether it should just be a new `life_domains` row instead. See
  `DECISIONS.md` D-001.
- **Priority scores are never cached** — `work_items.priority_score` is a
  reserved column, not the source of truth; every read recomputes via
  `src/lib/priority/from-db.ts`. If you ever start reading that column
  directly, you're introducing a staleness bug that doesn't exist today.
  See `DECISIONS.md` D-003.
- **`src/lib/priority/engine.ts` changes must keep `pnpm test` green** —
  the 22-fixture suite is the only real regression guard in this repo.
- **Don't touch the `<!-- BEGIN:nextjs-agent-rules -->`-style block in
  `AGENTS.md`.** Regenerated by `next dev` itself; hand-editing gets
  overwritten and removing it from a diff without committing just
  recreates the uncommitted change on every dev-server start.
- **Never write real secret values into any committed file.** `.env.local`
  (real Neon + Clerk creds) is gitignored; only `.env.example`
  (placeholders) is tracked. This matters more than usual here because the
  repo is public.
- **`.agents/skills/` and `.claude/skills/` are vendored Clerk/Neon
  reference skills, not application code.** Don't attribute their content
  (example `user_xxx` placeholders, ngrok URLs, etc.) to this app when
  scanning for secrets or markers — a repo-wide grep will surface them and
  they're noise.

## Known issues (see TASKS.md / FEATURES.md / ROADMAP.md for full detail)

- `habits` table has zero query/action/UI code anywhere — undocumented gap
  found 2026-08-17, not previously flagged. Needs a decision: build it or
  drop it.
- `notifications`, `daily_reviews`, `ai_summaries`, `notes`/`links`/
  `attachments` are schema-only, no UI (these ones *are* documented as
  known gaps, in `HANDOFF.md` originally and now `FEATURES.md`).
- `goal_relationships` isn't wired into any UI — Goals track progress
  manually.
- No CI, no E2E tests, only one Vitest suite.
